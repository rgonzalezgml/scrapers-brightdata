## genomma lab

### 1.
Scraper INPI para Investigacion y Desarrollo (I+D) de Genomma Lab, categoria registros por marcas. El INPI (Instituto Nacional de la Propiedad Industrial, Argentina) es la autoridad que administra el Registro Nacional de Marcas bajo la Ley 22.362. Proposito del scraper: consultar de forma sistematica el portal publico de tramites (portaltramites.inpi.gob.ar) para detectar actas y registros de marcas relevantes para la operacion de Genomma en Argentina (productos OTC, farmaceuticos, dermocosmetica, suplementos, dispositivos medicos, retail y servicios asociados). Casos de uso: (a) vigilancia defensiva sobre la cartera propia (renovaciones, oposiciones, caducidades), (b) vigilancia ofensiva sobre denominaciones nuevas en clases 3 cosmetica, 5 farma/OTC, 10 dispositivos medicos y 35 retail que puedan colisionar, (c) inteligencia competitiva (nuevas marcas de laboratorios y retailers). NO extraemos patentes, NO modelos de utilidad, NO modelos y disenos industriales, NO transferencias de tecnologia, NO tramites de agentes. El output unico es una fila por acta de marca (con su estado de vida: en tramite, concedida, denegada, caduca, abandonada, oposicion publicada).

### 2.
Infraestructura, anti-bot y encoding. Stack legacy del sitio: IIS 8.5 + ASP Classic, frontend con frames, iframes y formularios POST con querystring. Sesion via cookie ASPSESSIONID* y ademas cookie de sesion cookiesession1 del WAF. Observado 2026-04-21: el portal monta un Web Application Firewall tipo Radware AppWall / F5 Silverline (identifiable por el challenge JS inline ofuscado con variables tmevtre0..tmevtre6, fwb_dat, Za=, y un blob base64 que encodea el request GET original completo). Este WAF responde HTTP 200 a ciertos endpoints con cuerpo que contiene solo JS eval(...) ofuscado; un browser real lo ejecuta, hace un POST sub-recurso que setea cookie de paso y reintenta. Curl puro NO logra atravesarlo: endpoints criticos (MarConsultaAvanzada, MarConsultaPuntual) responden 404 de IIS a clientes sin cookie WAF incluso con Referer correcto. Consecuencia dura: el scraper DEBE correr en BrightData Scraping Browser con JS render activo; HTTP puro queda descartado. Proxy: residencial Argentina recomendado (el sitio es de consumo local, proxys de otros paises no disparan bloqueo adicional pero introducen latencia). Delay 3 a 5 segundos entre requests por host (sitio lento, tipico 2-4s por navegacion). Encoding mixto: home UTF-8 pero templates internos tienen declaraciones contradictorias (iso-8859-1 en algunos meta y UTF-8 en otros); tratar el output de resultados como UTF-8 y si aparece mojibake (patrones Ã©, Ã±, etc) aplicar re-decode latin1->utf8 y flag encoding_fix. Sesion nueva cada 30 consultas o cuando el WAF reset challenge. robots.txt permisivo: solo Disallow /Clasico/ (pero los forms publicos se acceden por path sin Clasico); no hay Crawl-delay ni Sitemap; ClaudeBot no bloqueado explicitamente.

### 3.
URLs canonicas y patrones de ID. Menu publico (anchor del crawl): https://portaltramites.inpi.gob.ar/Clasico/Docs/Index/IndexMarcas_SC.asp. Formulario de busqueda por denominacion y otros filtros: https://portaltramites.inpi.gob.ar/Docs/FormulariosConsultas/MarConsultaAvanzada.asp. Formulario de consulta puntual por nro de solicitud (acta) o nro de resolucion (registro): https://portaltramites.inpi.gob.ar/Docs/FormulariosConsultas/MarConsultaPuntual.asp. Ambos formularios hacen POST al mismo host sobre paginas de resultados bajo /Docs/ResultadosConsultas/ (nombre exacto a confirmar al correr el scraper con Scraping Browser; observado al 2026-04-21 solo el entry point). Indice de clases internacionales (taxonomia Niza 1..45): https://portaltramites.inpi.gob.ar/Clasico/Docs/ResultadosConsultas/GrillaClases.asp. Patrones de ID. Acta (nro de solicitud): entero, tipicamente 7 digitos (formato NNNNNNN, ej 3876543); es el PK canonico porque se asigna al momento de presentar el tramite y nunca cambia. Registro: entero mas corto (5-7 digitos) asignado al momento de conceder la marca; null mientras la marca esta en tramite. URL canonica de detalle (a confirmar en run): patron esperado /Docs/ResultadosConsultas/MarDetalle.asp?Acta={ACTA_ID} o query similar; guardar la URL completa como marca_url (clave permanente). Paginacion: las grillas de resultados usan tablas HTML con paginacion server-side via POST repetido con offset en campo oculto; max 500 resultados por denominacion segun reportes historicos del portal. Seeds primarias por corrida de Genomma: denominaciones de la cartera (nombres comerciales actuales y marcas en tramite ya conocidas) ademas de keywords de vigilancia ofensiva (nombres fonetica parecida). No hay sitemap XML.

### 4.
Entidad marca (unica). Campos siempre presentes: acta_id string (nro de solicitud, sin ceros a la izquierda, PK), marca_url string (URL absoluta del detalle), site_code string fijo inpi-ar, denominacion_original string (tal como figura en el registro, puede contener mayusculas y simbolos), tipo_marca enum denominativa mixta figurativa tridimensional sonora (denominativa default si no se expresa), clase_niza entero 1..45 (una sola clase por acta; si el registro abarca varias clases en INPI cada clase genera un acta distinta, tratarlas como filas separadas con mismo titular), status enum en_tramite publicada oposicion concedida denegada caduca abandonada en_renovacion vencida (ver punto 9 para mapeo de strings del sitio a este enum canonico), fecha_solicitud YYYY-MM-DD, scraped_date YYYY-MM-DD. Campos frecuentes con null explicito si faltan: registro_id string (nro de resolucion/registro una vez concedida), denominacion_clean string (punto 7), fecha_concesion YYYY-MM-DD, fecha_vencimiento YYYY-MM-DD, fecha_publicacion_boletin YYYY-MM-DD, nro_boletin string (formato BNNNNN o similar), vigente bool (derivado), titular_nombre_raw string (razon social o persona fisica tal como aparece), titular_cuit string (11 digitos sin guiones si se expone), titular_pais string ISO-2 (AR default, OTRO si address extranjero), agente string (matricula del agente de propiedad industrial si figura), productos_servicios string (descripcion de productos/servicios reivindicados, puede ser multi-linea), imagen_url string (URL absoluta del logo si es marca mixta o figurativa), scraper_flags lista de strings.

### 5.
Campos derivados y entidad titular inline. vigente bool derivado: true si status in {concedida, en_renovacion} y fecha_vencimiento >= scraped_date; false en cualquier otro caso (en_tramite, denegada, caduca, abandonada, vencida, oposicion sin resolver). fecha_vencimiento derivada: si no figura explicita en el detalle pero hay fecha_concesion, calcular fecha_concesion + 10 anos (duracion legal art. 5 Ley 22.362) y flag vencimiento_derivado; si hay renovaciones posteriores el detalle las expone y se toma la ultima. dias_hasta_vencimiento entero derivado (fecha_vencimiento - scraped_date). No emitimos entidad titular separada en v1: el titular va inline como titular_nombre_raw, titular_cuit, titular_pais. Si mas adelante se necesita cross-referenciar marcas por titular se promueve a entidad secundaria (backlog, no implementar ahora). Imagenes: solo guardar imagen_url; no descargar binarios. productos_servicios: mantener literal sin normalizar; si excede 2000 caracteres truncar y flag productos_truncado.

### 6.
Skip rules - cuando NO emitir fila. SKIP sin emitir cuando: (a) HTTP 404/410 en detail, (b) acta_id no se pudo extraer (parse falla o resultado vacio), (c) denominacion_original vacia y ademas imagen_url null (no hay nada que registrar), (d) resultado pertenece a tipo distinto de marca (ej. el portal devuelve tambien patentes/disenos si se confunde form; filtrar por header del detalle), (e) status indica borrado administrativo limpio (status en el raw contiene desistida_sin_publicar y fecha_solicitud null). FLAG sin skip cuando: challenge WAF reintentado (flag waf_retry), encoding fix aplicado (flag encoding_fix), titular_cuit no extraible (flag titular_cuit_missing), fecha_vencimiento derivada de +10 anos (flag vencimiento_derivado), productos_servicios truncado (flag productos_truncado), clase_niza no detectada (flag clase_missing; no skip pero marca para revision manual), denominacion_clean fallback al raw (flag name_clean_fallback).

### 7.
Reglas de clean_name / parsing de denominacion. denominacion_clean sobre denominacion_original: normalizar unicode NFKC, colapsar whitespace a un espacio, quitar comillas tipograficas “”«»‘’, quitar asteriscos y hashes, quitar subfijos tipo (R), ®, TM, ™, (MR), (MARCA REGISTRADA) case-insensitive, quitar paren largos entre parentesis > 30 chars (texto descriptivo del producto suele aparecer ahi), quitar prefijo/sufijo clase "CLASE 5" si se filtro por error, upper-case final, max 120 caracteres cortando en ultimo espacio, trim. Si queda cadena vacia fallback a denominacion_original y flag name_clean_fallback. Fechas: el portal las expone como DD/MM/YYYY; convertir a ISO YYYY-MM-DD; si falla parse emitir null y flag fecha_parse_error. Nro de boletin: formato observado "Boletin N° 12345" o "B12345"; extraer solo digitos, prefijar B, emitir como string "B12345". titular_cuit: regex \b(20|23|24|25|26|27|30|33|34)[-]?\d{8}[-]?\d\b; normalizar a 11 digitos seguidos sin guiones; si el campo no expone CUIT (solo nombre) dejar null.

### 8.
Clasificacion (clases de Niza) y scoping Genomma. INPI trabaja con la clasificacion internacional de Niza (edicion vigente al momento del tramite). Clases relevantes para Genomma Lab: 3 (cosmeticos, productos de perfumeria, productos de tocador), 5 (productos farmaceuticos, suplementos dieteticos, productos higienicos para medicina, parches, desinfectantes), 10 (aparatos e instrumentos medicos, articulos ortopedicos), 35 (servicios de venta al por menor y publicidad). Por default la corrida filtra resultados a clase_niza in {3,5,10,35}; parametrizable via `classes` input del collector para ampliar a toda la taxonomia 1..45 si el usuario lo pide. Cada acta expone una sola clase; una marca multi-clase en Argentina se registra como varias actas distintas con misma denominacion y mismo titular, lo cual debe respetarse (una fila por acta, no deduplicar por denominacion). El indice de clases Niza esta en GrillaClases.asp y sirve para validar que clase_niza extraido cae en 1..45; si no cae flag clase_invalida y skip.

### 9.
Mapeo de status. El portal INPI expone el estado en lenguaje natural en español; canonizar a enum controlado: "En tramite" / "En proceso" / "Presentada" -> en_tramite; "Publicada" / "Publicada en Boletin" -> publicada (fase de oposicion abierta); "Con oposicion" / "En oposicion" -> oposicion; "Concedida" / "Registrada" -> concedida; "Denegada" / "Rechazada" -> denegada; "Caduca" / "Caducada" / "Vencida por caducidad" -> caduca; "Abandonada" / "Desistida" -> abandonada; "En renovacion" / "Solicitud de renovacion" -> en_renovacion; "Vencida" (sin caducidad administrativa, solo por no renovar) -> vencida. Si el string del sitio no matchea ninguna categoria emitir status raw en status_raw, status null y flag status_desconocido (NO skip - queremos ver la marca igual).

### 10.
Output y limites de corrida. Emitir array JSON inpi_marcas_{YYYYMMDD}.json y resumen inpi_run_{YYYYMMDD}.json con started_at, ended_at, requests, blocked, waf_challenges, emitted, skipped_by_reason, errors. UTF-8, fechas ISO 8601, numeros siempre numericos (no strings), todas las claves presentes con null explicito cuando falten, listas vacias nunca null. Dedupe estricto por acta_id dentro de la corrida. Cache 24h por acta_id para no reabrir el mismo detalle el mismo dia. Hard caps por corrida default: 800 denominaciones consultadas, 5000 actas detail, 120 minutos wall time, lo primero que se cumpla corta. Limite de pagina del portal: el form de busqueda devuelve hasta 500 resultados por denominacion; si se alcanza ese cap, emitir flag busqueda_saturada a nivel run (no a nivel fila) y considerar refinar con filtro de clase. Flags permitidos en scraper_flags: waf_retry, encoding_fix, titular_cuit_missing, vencimiento_derivado, productos_truncado, clase_missing, clase_invalida, name_clean_fallback, fecha_parse_error, status_desconocido, imagen_url_missing. Prohibido inventar campos fuera de los definidos en puntos 4 y 5. No extraer datos de patentes, modelos, disenos industriales ni transferencias aunque el portal los exponga en otros menues.

Patrones de acta sugeridos para validacion en primer run (Genomma Argentina tiene marcas historicas publicas: Tafirol, Lomecan, X-Ver, Bagovit, Asepxia, Vanart, etc.). Buscar por denominacion "TAFIROL" en clase 5, "ASEPXIA" en clase 3, "BAGOVIT" en clase 3, tomar las primeras 3 actas de cada una y documentar marca_url real + acta_id real + status real en este punto una vez completada la primera corrida. Hasta entonces este bloque queda como placeholder intencional: no inventamos IDs.

Bloqueadores duros conocidos al 2026-04-21:
- WAF tipo Radware/F5 con challenge JS - Scraping Browser mandatorio.
- Portal legacy ASP Classic - timeouts de sesion de ~20 minutos, hay que manejar renovacion de cookie ASPSESSIONID.
- Formularios POST con campos ocultos (viewstate-like) - el collector debe primero GET del form, extraer hidden inputs, y reenviar POST con mismos valores + denominacion.
- Encoding mixto latin1/utf8 en templates internos - aplicar re-decode defensivo.
- Sin API JSON publica - todo el extraction es sobre HTML tables.
- Motion captcha en login (no bloquea busqueda publica que es sin login, pero si alguna vez se quisiera consultar un detalle que requiera login, ese captcha hace inviable automatizar sin intervencion manual).
