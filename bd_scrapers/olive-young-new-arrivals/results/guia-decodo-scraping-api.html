Guía: Decodo Web Scraping API

Tutorial completo desde cero — autenticación, parámetros, browser actions, tipos de request y recetas listas.

REST API JS Rendering Browser Actions Anti-bot bypass

¿Qué es la Decodo Web Scraping API?

Una API REST totalmente administrada que se encarga de los proxies, el browser remoto, los CAPTCHAs y los mecanismos anti-bot. Tu trabajo es enviar un JSON con la URL y los parámetros, y Decodo te devuelve el HTML (o JSON, o screenshot).

Pasos para empezar

1

Crear cuenta y obtener tu token

Entra a dashboard.decodo.com → activa un trial o plan → ve al API Playground para copiar tu Authorization Token.

2

Endpoint único para todas las requests

POST https://scraper-api.decodo.com/v2/scrape

3

Autenticación: Basic Token

Header: Authorization: Basic TU_TOKEN — el token se obtiene directo del dashboard, no es user:pass en base64.

Primera request — cURL

cURL
curl --request 'POST' \
  --url 'https://scraper-api.decodo.com/v2/scrape' \
  --header 'Authorization: Basic TU_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "url": "https://example.com"
  }'

Respuesta típica

JSON — Respuesta
{
  "results": [
    {
      "content": "<html>...</html>",   // HTML de la página
      "status_code": 200,
      "task_id": "7422278918918391809",
      "created_at": "2026-01-28 14:06:33",
      "updated_at": "2026-01-28 14:06:35"
    }
  ]
}

Ejemplo en Python

Python
import requests

payload = {
    "url": "https://example.com",
    "headless": "html",  # activa JS rendering
    "geo": "United States",
    "proxy_pool": "premium"
}

response = requests.post(
    "https://scraper-api.decodo.com/v2/scrape",
    headers={
        "Authorization": "Basic TU_TOKEN",
        "Content-Type": "application/json"
    },
    json=payload,
    timeout=60
)

data = response.json()
html = data["results"][0]["content"]
print(html[:500])

Se pasan todos en el body JSON. Solo url es obligatorio (o query para algunos target templates).

Browser Actions

Acciones que el browser remoto ejecuta antes de devolverte el resultado. Se pasan en el array browser_actions. Requiere headless: "html".

click
Clic en un elemento
input
Escribe en un campo
scroll
Scroll a coordenadas
scroll_to_bottom
Scroll continuo
wait
Pausa fija
wait_for_element
Espera que aparezca algo
fetch_resource
Captura XHR / API calls

Tipos de selector

typeEjemplo de value
css.btn-load-more · #search-input · button[type="submit"]
xpath//button[@class='submit'] · //input[@name='q']
textLoad more (texto visible del elemento)

on_error — manejo de errores por acción

valorcomportamiento
errorDetiene toda la ejecución al primer error.
skipIgnora esa acción y continúa con la siguiente. Útil para elementos opcionales.

Ejemplo: secuencia completa de acciones

JSON — Secuencia combinada
{
  "url": "https://tienda.com/categoria",
  "headless": "html",
  "browser_actions": [
    {
      "type": "wait_for_element",       // 1. Esperar que cargue la grilla
      "selector": { "type": "css", "value": ".product-grid" },
      "timeout_s": 10
    },
    {
      "type": "scroll_to_bottom",          // 2. Scroll para cargar más items
      "timeout_s": 4
    },
    {
      "type": "wait",                     // 3. Pausa para que carguen los nuevos items
      "wait_time_s": 2
    },
    {
      "type": "click",                    // 4. Clic en "Ver más" si existe
      "selector": { "type": "css", "value": ".load-more" },
      "on_error": "skip"               // continúa si no existe el botón
    }
  ]
}

Tipos de request

La request bloquea hasta recibir el resultado. Timeout máximo ~60 segundos. Ideal para scripts simples y requests individuales. La respuesta llega directamente en el body.

Python — Síncrona
response = requests.post(
    "https://scraper-api.decodo.com/v2/scrape",
    headers={
        "Authorization": "Basic TU_TOKEN",
        "Content-Type": "application/json"
    },
    json={"url": "https://ejemplo.com", "headless": "html"},
    timeout=65
)
html = response.json()["results"][0]["content"]

Envías la request con el header x-response-type: task, recibes un task_id, y luego haces polling para recuperar el resultado. Permite correr muchas requests en paralelo sin bloquear.

Python — Asíncrona (polling)
import requests, time

HEADERS_BASE = {
    "Authorization": "Basic TU_TOKEN",
    "Content-Type": "application/json"
}

# 1. Encolar la tarea
r = requests.post(
    "https://scraper-api.decodo.com/v2/scrape",
    headers={**HEADERS_BASE, "x-response-type": "task"},
    json={"url": "https://ejemplo.com"}
)
task_id = r.json()["id"]
print(f"Task encolado: {task_id}")

# 2. Polling hasta que esté listo
while True:
    result = requests.get(
        f"https://scraper-api.decodo.com/v2/task/{task_id}",
        headers=HEADERS_BASE
    ).json()

    status = result.get("status")
    if status == "done":
        html = result["results"][0]["content"]
        print(f"Listo: {len(html)} chars")
        break
    elif status == "failed":
        raise Exception(f"Task falló: {result}")

    time.sleep(2)  # esperar 2 segundos entre polling

Envías múltiples URLs en una sola request. Útil para scrapear listas de productos, páginas de categoría, etc. El endpoint de batch acepta un array de tareas.

Python — Batch
import requests

urls = [
    "https://ejemplo.com/producto/1",
    "https://ejemplo.com/producto/2",
    "https://ejemplo.com/producto/3",
]

tasks = [
    {"url": url, "headless": "html", "proxy_pool": "premium"}
    for url in urls
]

# Enviar batch
response = requests.post(
    "https://scraper-api.decodo.com/v2/batch",
    headers={
        "Authorization": "Basic TU_TOKEN",
        "Content-Type": "application/json"
    },
    json={"tasks": tasks}
)

batch_id = response.json()["batch_id"]
print(f"Batch ID: {batch_id}")
# Luego hacer polling por cada task_id igual que en async...
ℹ Para volúmenes grandes de URLs, el modo batch es la forma más eficiente: envías todo junto y recuperas los resultados cuando están listos.

Recetas listas para usar

Patrones comunes que puedes adaptar directamente a tus scrapers.

1. Página con infinite scroll

Para sitios que cargan más productos al bajar (como @cosme, Rakuten, etc.).

JSON
{
  "url": "https://tienda.com/categoria/serums",
  "headless": "html",
  "proxy_pool": "premium",
  "geo": "Japan",
  "browser_actions": [
    { "type": "wait_for_element",
      "selector": { "type": "css", "value": ".product-list" },
      "timeout_s": 10 },
    { "type": "scroll_to_bottom", "timeout_s": 5 },
    { "type": "wait", "wait_time_s": 2 },
    { "type": "scroll_to_bottom", "timeout_s": 5 }
  ]
}

2. Búsqueda con formulario

Escribir en un campo de búsqueda, hacer submit y esperar los resultados.

JSON
{
  "url": "https://nutraingredients.com",
  "headless": "html",
  "browser_actions": [
    { "type": "input",
      "selector": { "type": "css", "value": "input[name='q']" },
      "value": "retinol 2026" },
    { "type": "click",
      "selector": { "type": "css", "value": "button[type='submit']" } },
    { "type": "wait_for_element",
      "selector": { "type": "css", "value": ".search-results" },
      "timeout_s": 10 }
  ]
}

3. Capturar API interna (XHR/fetch)

Si el sitio carga datos vía XHR o fetch, puedes capturar esa respuesta directamente como JSON, evitando parsear HTML.

JSON
{
  "url": "https://sitio.com/productos",
  "headless": "html",
  "browser_actions": [
    {
      "type": "fetch_resource",
      "filter": "/api/v1/products",  // regex que matchea la URL del XHR
      "on_error": "error"
    }
  ]
}
// ⚠ fetch_resource NO puede combinarse con otras acciones en la misma request

4. Google Search con datos estructurados

JSON
{
  "target": "google_search",
  "query": "retinol skincare ingredients trends",
  "geo": "Japan",
  "locale": "ja-JP",
  "parse": true   // devuelve JSON estructurado, no HTML
}

5. Respuesta en Markdown (para LLMs)

Convierte el HTML en Markdown limpio, reduciendo tokens para procesamiento con modelos de lenguaje.

JSON
{
  "url": "https://nutraingredients.com/article/ejemplo",
  "headless": "html",
  "proxy_pool": "premium",
  "markdown": true   // retorna Markdown en vez de HTML crudo
}

6. Mantener sesión entre requests (mismo IP)

Útil cuando necesitas navegar varias páginas simulando el mismo usuario.

Python — Session ID
session_id = "mi-sesion-123"  # cualquier string fijo

for url in ["/pagina1", "/pagina2", "/pagina3"]:
    requests.post(
        "https://scraper-api.decodo.com/v2/scrape",
        headers={"Authorization": "Basic TU_TOKEN", ...},
        json={
            "url": f"https://sitio.com{url}",
            "session_id": session_id  # mantiene el mismo IP
        }
    )
⚠ Límite importante: Decodo no soporta scraping de datos post-login (páginas que requieren autenticación). Solo funciona con contenido de acceso público.
⚠ fetch_resource solo puede usarse sola en una request. No puede combinarse con click, scroll u otras acciones.
